# Drill Library: Searchable, Filterable Skill-Progression Roadmap

Date: 2026-08-19
Status: Approved for implementation (Track A) via `/build-grok`

## Problem

The Practice Planner's drill library (368 drills, 47 pre-built plans) already
supports search and skill/intensity/age filtering, but two things keep it
from being a genuine "introductory → U15" progression tool:

1. **No explicit skill-level/stage data.** Drills carry `intensity`
   (physical exertion) but nothing that represents skill difficulty or where
   a drill sits in a learning progression. The 47 existing plans carry a
   free-text `difficultyRange` (e.g. "Beginner–Intermediate") but it isn't a
   structured field, and it isn't present on individual drills at all.
2. **No roadmap.** There is no view that shows a coach or player how skills
   build on each other over time — only a flat list of skill-tagged plans
   and a flat, filterable drill grid.

Separately, the age distribution is heavily skewed older: only 11 of 368
drills have `ageMin` under 8, so a genuine "Introductory" (5–8U) tier is
almost empty today, even though the UI already advertises a "5–8U (T-Ball)"
age filter band.

The KB source (`/Users/jschasse/knowledge-base/youth-baseball-canada/wiki/drills/*.md`)
already contains relevant content the app currently discards: 252/370 drill
files have a `**Progressions:**` note and 114/370 have an
`**Age/division notes:**` note, both ignored by `scripts/sync-drills.mjs`.

## Goals

- Drill library search/filter is complete, professional, and scalable from
  introductory level through U15.
- A skill-progression roadmap lets a coach/player see, per skill category,
  the stages of development and jump straight into a stage's plan.
- Ship this without blocking on a full KB content rewrite — 370 drills is a
  large, ongoing editorial effort that must not gate the app release.

## Non-goals

- Rewriting or hand-retagging all 370 KB drill files (Track B, tracked
  separately, not part of this implementation pass).
- Authoring new introductory-level (5–8U) drill content (also Track B).
- Any change to the five brand hex values, PDF/print output structure, or
  the save/load/export data formats beyond the additive fields below.

## Design overview

Two tracks, decoupled by a fallback so Track A is fully functional before
any Track B content lands:

- **Track A — App** (this repo, implemented now via `/build-grok`): sync
  script changes, new `stage` computation with graceful fallback, a new
  Roadmap view, a Level filter, card/detail polish, docs.
- **Track B — KB content** (outside this repo, follow-on work run
  separately, not part of this plan): explicit `stage` frontmatter on all
  370 drills, new Introductory-tier drills, new Introductory-tier plans.

Because Track A computes a `stage` fallback whenever the KB hasn't supplied
one explicitly, the app is correct and demoable today, and silently gets
more accurate as Track B content is added later — no app code changes
required when that happens.

## Data model changes

### Drill record (`src/drills-data.js`, generated by `scripts/sync-drills.mjs`)

New optional fields, all backward compatible (absent in KB today):

- `stage: 'introductory' | 'beginner' | 'intermediate' | 'advanced'` — read
  from a new `stage:` frontmatter key on the KB drill file when present.
- `prerequisites: string[]` — drill-slug IDs, from a new `prerequisites:`
  frontmatter key (inline YAML list). Empty array when absent.
- `progressionNotes: string` — parsed from the existing `**Progressions:**`
  inline-bold section (or `## Progressions` heading section for the 2 "long"
  format files), same extraction pattern as `extractSetup`/`extractCues`.
  Empty string when absent.
- `ageNotes: string` — parsed from the existing `**Age/division notes:**`
  inline-bold section (or `## Age...` heading section), same pattern. Empty
  string when absent.

### Stage fallback computation

When a drill's frontmatter has no `stage`, `scripts/sync-drills.mjs` computes
one at sync time from `ageMin` and `intensity` so every drill always has a
usable `stage` in the output:

| ageMin range | intensity | computed stage |
|---|---|---|
| ≤ 8 | any | `introductory` |
| 9–10 | low/medium | `beginner` |
| 9–10 | high | `intermediate` |
| 11–12 | any | `intermediate` |
| ≥ 13 | any | `advanced` |

This table is a starting heuristic, not a claim of precision — it exists
only so the UI has something honest to show before Track B supplies
authored values. The sync script emits a summary count of how many drills
used the fallback vs. an explicit `stage`, so KB tagging progress
(Track B) is visible in the sync output over time (`npm run sync:drills`).

### Plan record (`standard-plans.md` / generated plan objects)

New `stage:` field (same 4-value enum) alongside the existing
`difficulty_range:` free-text field, which is kept as-is for its current
display purpose. `stage` is the field the Roadmap view groups on;
`difficultyRange` remains the human-readable label already shown on plan
cards. Plans without an explicit `stage:` line fall back to a lookup from
their existing `difficultyRange` text (`"Beginner"` → `beginner`, etc.);
introductory plans that don't exist yet simply don't appear (see Roadmap
view below — a missing stage renders as "coming soon", not an error).

## App changes (Track A)

### `scripts/sync-drills.mjs`

- Parse `stage` and `prerequisites` frontmatter into each drill record.
- Parse `progressionNotes` and `ageNotes` via new extractor functions
  mirroring the existing `extractSetup`/`extractCues` dual-format handling
  (inline-bold for the 368 "concept" files, heading-section for the 2
  "long" files).
- Apply the stage fallback table when `stage` is absent; track and log a
  count of fallback-vs-explicit drills to console output.
- Parse `stage:` on plan entries in `standard-plans.md`; fall back to a
  `difficultyRange` → `stage` lookup when absent.
- No output schema keys are removed; this is purely additive, so existing
  `practice.js` code keeps working unchanged during rollout.

### New "Roadmap" view

A new tab/section (alongside Drill Library, Skill-Focused Plans) presented
per skill category as a horizontal 4-stage ladder: Introductory → Beginner →
Intermediate → Advanced. Each stage renders as a card:

- If one or more plans exist at that skill×stage: show the plan(s) (label,
  age range, drill count, total duration); clicking loads it into the plan
  builder exactly like the existing Skill-Focused Plans click-to-load
  behavior (reuses that existing code path, not a new one).
- If no plan exists yet at that skill×stage: render a visually distinct
  "Coming soon" placeholder card rather than omitting the stage — the
  roadmap always shows the full 4-stage shape for every skill, honestly
  representing what's built vs. planned.

Age labels on each stage reflect the U15 ceiling this project targets:
Introductory 5–8U, Beginner 8–10U, Intermediate 10–12U, Advanced 12–15U
(capped display at 15U even where underlying drill `ageMax` values are
higher — those drills remain usable, just not advertised past the roadmap's
top rung).

### Drill Library filter/search/card updates

- New **Level** filter control (Introductory/Beginner/Intermediate/Advanced)
  alongside the existing Skill, Intensity, Age Range filters, driven by
  `drill.stage`.
- Existing Age Range filter's top option changes label from open-ended
  "14U+ (Junior/Senior)" to a capped **"12–15U (Advanced)"**, consistent
  with the U15 scope; underlying filter logic (age-overlap match) is
  unchanged, only the option's bounds/label move.
- Drill card gains a **Level** badge alongside the existing skill/intensity
  badges.
- Drill detail modal surfaces `progressionNotes` (as a "How to progress"
  note) and `prerequisites` (as clickable chips that jump to/open that
  drill) when non-empty; hidden entirely when empty, no placeholder text.
- Full-text search (`filterDrills`) extends its searchable-fields list to
  include `progressionNotes` and `ageNotes`.

### Docs

- [README.md](../../../README.md): document the new `stage`,
  `prerequisites`, `progressionNotes`, `ageNotes` fields under "Drill data",
  and describe the Roadmap view under "The Practice Planner".
- `scripts/README.md`: document the stage-fallback behavior and the
  fallback/explicit count the sync script logs.

## Testing

- `scripts/sync-drills.mjs` — dry-run (`--dry-run`) against the current KB
  must still succeed with 0 errors; spot-check that fallback stage counts
  print and are sane (~all 368 drills fallback today, 0 explicit, since
  Track B hasn't landed).
- Manual verification in the app (via the existing `run` skill / browser
  preview): Roadmap view renders all 10 skill categories × 4 stages;
  "coming soon" cards appear for every Introductory cell (since no
  Introductory plans exist yet) and for any other empty skill×stage
  combination; clicking a populated stage card loads that plan into the
  builder; Level filter narrows the Drill Library grid correctly; search
  matches text now sourced from `progressionNotes`/`ageNotes` on drills
  that have it; print/PDF output is unaffected.
- No regression to existing save/load, export/import, or print flows —
  none of their data shapes change.

## Track B (explicitly out of scope for this implementation pass)

Tracked here for continuity, not part of `/build-grok`'s task:

- Explicit `stage` retagging across all 370 KB drill files (replacing
  fallback-computed values with authored ones).
- New Introductory-tier (5–8U) drills authored per skill category where
  coverage is thin today (infield, hitting, throwing, catching,
  conditioning need the most).
- New Introductory-tier plans in `standard-plans.md` for each of the 10
  skill categories, built from the new drills above.
- Run via `kb-manager`/`kb-fill` against the KB directly, synced into this
  app afterward with no app-code changes required (Track A already
  consumes `stage` when present).
