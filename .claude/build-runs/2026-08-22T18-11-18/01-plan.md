## Goal

Add demonstration-video links to the Practice Planner's drill library. For
drills where a good-quality, publicly available demo video was found
(researched via web search ahead of this build — see
`researched-videos.json` in this run directory, 85 of the app's 391 drills),
the drill card and the drill detail modal should show a distinctive red
camera icon. Clicking that icon opens the video in a new browser tab
(`target="_blank" rel="noopener noreferrer"`) without triggering the card's
existing "open detail" click handler. Drills with no researched video get no
icon and are otherwise completely unchanged. This is an additive UI/data
feature — no existing drill fields, filtering behavior, plan-building
behavior, or print/export output change.

## Constraints

- `src/drills-data.js` is auto-generated by `scripts/sync-drills.mjs` from
  the knowledge-base markdown source and is marked "DO NOT EDIT BY HAND" —
  do not hand-edit it and do not modify the sync script's KB-reading logic.
  Video data must live in a **new, separate** data file
  (`src/drill-videos-data.js`) that the app merges in at runtime, the same
  pattern the codebase already uses for `window.DRILLS_DATA` (see
  `src/drills-data.js:6`).
- The new file must set a single global, e.g. `window.DRILL_VIDEOS_DATA`, as
  a plain object keyed by drill `id` with `{ url, title }` values — copy the
  content directly from `researched-videos.json` in this run directory (the
  `_comment` key is metadata for humans only and must NOT be copied into the
  generated JS file).
- `index.html` must load `src/drill-videos-data.js` with a `<script>` tag
  placed immediately after the existing `src/drills-data.js` script tag (so
  load order matches: drills first, video overlay second) — read
  `index.html` first to find exactly where that existing tag lives.
- Video icon must appear in two places: the drill card (`buildDrillCard` in
  `practice.js`) and the drill detail modal header (`openDrillDetail` in
  `practice.js`).
- The icon must be visually distinctive — red, camera-shaped — and must not
  be confused with the existing add-to-plan `+` button. Use an inline SVG or
  a Unicode camera glyph (📹 or 🎥) styled red; either is acceptable as long
  as it reads clearly as "video available" at a glance, in both the compact
  card and the larger modal header, and remains legible in whatever
  light/dark theme handling `styles.css` already uses (check `styles.css`
  for existing theme/color-variable conventions before hardcoding a color).
- The link must open in a new tab: use `target="_blank"` and
  `rel="noopener noreferrer"` on the anchor.
- Clicking the video icon/link on a **card** must call `e.stopPropagation()`
  (same pattern already used for the existing `+` add button at
  `practice.js:303-306`) so it does not also trigger `openDrillDetail`.
- Do not alter `buildBadge`, `intensityClass`, filtering logic
  (`filterDrills`), plan management, PDF/print/export code, or any existing
  CSS class names — only add new ones.
- No network calls at runtime — the video URL is static data baked into the
  new JS file; there is no live lookup.
- Accessibility: the video link/icon needs an `aria-label` describing the
  action (e.g. `"Watch demo video for " + drill.title`) since it conveys
  meaning via icon/color alone.
- Follow the existing code style in `practice.js` (ES5-ish function
  declarations, `document.createElement` DOM building, no build step, no new
  dependencies).

## File List

- `src/drill-videos-data.js` — **new file**. Sets
  `window.DRILL_VIDEOS_DATA = { <drillId>: { url, title }, ... }` from the
  85 entries in `researched-videos.json` (this run's directory).
- `index.html` — add one `<script src="src/drill-videos-data.js"></script>`
  tag immediately after the existing `drills-data.js` tag.
- `practice.js` — in `buildDrillCard`, add a small red camera icon/link next
  to (not replacing) the existing add button when
  `window.DRILL_VIDEOS_DATA[drill.id]` exists. In `openDrillDetail`, add the
  same icon/link in the header area near the title/badges when a video
  exists for that drill.
- `styles.css` — add new, additive CSS classes for the video icon/link (card
  and modal variants). Do not modify existing classes.

## Acceptance Criteria

1. `src/drill-videos-data.js` exists, defines `window.DRILL_VIDEOS_DATA` as
   a plain object, contains exactly the 85 drill IDs from
   `researched-videos.json` (no more, no fewer, no `_comment` key), and each
   value has non-empty `url` (starting with `https://www.youtube.com/`) and
   `title` strings.
2. `index.html` loads `src/drill-videos-data.js` via a `<script>` tag placed
   immediately after the `src/drills-data.js` tag, and the file parses with
   no JS syntax errors (`node --check`).
3. For any drill whose `id` is a key in `DRILL_VIDEOS_DATA`, its card
   (rendered by `buildDrillCard`) shows a red camera icon that is a link
   with `target="_blank"` and `rel="noopener noreferrer"` pointing at the
   researched `url`, and clicking it does not also open the drill detail
   modal (verified by the click handler calling `stopPropagation`).
4. For any drill whose `id` is **not** a key in `DRILL_VIDEOS_DATA`, its card
   renders with no video icon and is pixel-for-pixel unchanged from current
   behavior otherwise.
5. The drill detail modal (`openDrillDetail`) shows the same red camera
   icon/link near the title for drills with a video, opening the same URL
   in a new tab; drills without a video show no icon in the modal.
6. The video icon/link has an `aria-label` naming the action and the drill
   title.
7. No existing drill card behavior changes: search/filter counts, the `+`
   add-to-plan button, badges, and the existing click-to-open-detail
   behavior on the rest of the card all work exactly as before.
8. `practice.js` and `index.html` still parse/load with no new console
   errors when the app is opened in a browser (spot-checked by the
   reviewer).
9. No changes to `src/drills-data.js`, `scripts/sync-drills.mjs`, PDF/export
   code, or plan-building logic.
