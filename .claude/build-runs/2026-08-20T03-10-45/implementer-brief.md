# Implementer Brief: Drill Library Level Filter + Skill-Progression Roadmap

You are implementing Track A of a design spec for the Homerun Practice app
(a vanilla-JS, no-build-step, offline browser app for baseball coaches). Read
`docs/superpowers/specs/2026-08-19-drill-library-roadmap-design.md` first for
full context — this brief summarizes what to build; the spec explains why.

## Goal

Add skill-level/progression data and a new "Roadmap" view to the drill
library so it reads as a searchable, filterable, professional path from
Introductory (5–8U) through U15 (capped display at 12–15U). The sync script
(`scripts/sync-drills.mjs`) gains a `stage` field per drill/plan (explicit
from KB frontmatter when present, computed via a fallback table otherwise)
plus two new text fields (`progressionNotes`, `ageNotes`) parsed from KB
content that already exists in the source markdown but is currently
discarded by the sync script. The app then exposes a Level filter, a Level
badge, progression/prerequisite info in the drill detail modal, and a new
Roadmap view showing each skill category as a 4-stage ladder that reuses the
existing "load plan into builder" behavior. This requires zero KB content
changes — the fallback table makes it fully functional today.

## Constraints

  hand-edit `src/drills-data.js` directly. Change the sync script, then run
  it to regenerate the file.
- The sync script's output schema changes must be purely additive — do not
  remove or rename any existing key on drill or plan records.
- Do not touch the five brand hex values in `styles.css`, the print/PDF
  output structure, or the save/load/export/import JSON formats used by
  `practice.js`.
- Reuse the EXISTING Skill-Focused Plans "click to load into plan builder"
  code path for the Roadmap view's populated stage cards — do not write a
  second, parallel load mechanism. Find the existing function that handles
  clicking a plan card in the Skill-Focused Plans section and call it (or a
  shared helper it already uses) from the new Roadmap cards.
- Do NOT edit any files under the KB path
  (`/Users/jschasse/knowledge-base/...`) — it is read-only source of truth
  for the sync script. This task adds no new KB frontmatter; the fallback
  table covers every drill for now.
- All 10 skill categories must appear in the Roadmap view: throwing,
  infield, conditioning, catching, hitting, pitching, outfield, baserunning,
  situational, bunting.
- A skill×stage cell with no existing plan must render as a distinct
  "Coming soon" card, not be hidden — the roadmap always shows the full
  4-stage shape (Introductory/Beginner/Intermediate/Advanced) for every
  skill, even when most cells are empty today.
- Follow existing code style: vanilla JS (no new dependencies, no build
  step, no TypeScript, no framework), matching the patterns already used in
  `practice.js` (IIFE module pattern, `document.getElementById`,
  `makeBadge`-style helpers) and `styles.css` (existing CSS custom
  properties / badge class naming conventions like `pbadge-low`,
  `pbadge-med`, `pbadge-high`).
- This is a static site (no server, no bundler) — files load via `<script>`
  tags in `index.html` in a fixed order; if you add new functions to
  `practice.js` they must not depend on load order changes.

## File List

- `scripts/sync-drills.mjs` — parse `stage`/`prerequisites` frontmatter,
  compute a stage fallback when absent, extract `progressionNotes`/
  `ageNotes` from drill markdown bodies, parse plan `stage:` (falling back
  to a `difficultyRange`-derived value), log a fallback/explicit summary
  count to console on sync.
- `src/drills-data.js` — regenerated output. Do not hand-edit; produce it by
  running `npm run sync:drills` after the script changes above.
- `practice.js` — Level filter state/wiring, `filterDrills()` search-field

  notes/prerequisite chips in the drill detail modal, new `renderRoadmap()`

- `index.html` — new Level `<select>` filter control in the Drill Library
  controls, relabeled top Age Range filter option, new Roadmap tab/section
  markup (matching the existing tab pattern for Drill Library / Skill-
  Focused Plans).
- `styles.css` — stage badge color variants (4 new badge classes following
  the existing `pbadge-low/med/high` pattern), plus styling for the Roadmap
  view (ladder layout, stage cards, "coming soon" card variant) — reuse
  existing card/badge/button classes and CSS custom properties where

- `README.md` — document the new drill fields under "Drill data" and
  describe the new Roadmap view under "The Practice Planner" (as a new
  numbered item, matching the existing style).
- `scripts/README.md` — document the stage-fallback table and the
  fallback/explicit count now logged by the sync script.

## Step-by-Step Implementation Plan

1. In `scripts/sync-drills.mjs`, read `fm.stage` (string) and
   `fm.prerequisites` (inline YAML list — `parseFrontmatter` already parses
   `[a, b]`-style values generically; default to `[]` when absent) in
   `loadDrills()`.

2. Add a `stageFallback(ageMin, intensity)` helper function implementing
   this table (apply in order, first match wins):
   - `ageMin <= 8` → `'introductory'`
   - `ageMin` is 9 or 10, and `intensity` is `'low'` or `'medium'` →
     `'beginner'`
   - `ageMin` is 9 or 10, and `intensity` is `'high'` → `'intermediate'`
   - `ageMin` is 11 or 12 (any intensity) → `'intermediate'`
   - `ageMin >= 13` → `'advanced'`

3. Add two extractor functions mirroring the existing dual-format pattern
   used by `extractSetup`/`extractCues` (look at those two functions in the
   file for the exact pattern to copy — Format 1 is an inline
   `**Label:**` bold marker, Format 2 is a `## Heading` section handled via
   the existing `headingSection()` helper):
   - `extractProgressionNotes(body)`: Format 1 — inline
     `**Progressions:**` bold section (same style of regex as
     `extractSetup`'s Format 1 match, but matching the label
     `Progressions`); Format 2 — a `headingSection(body, /^progressions$/i)`
     section, joined into a single paragraph string the same way
     `extractSetup`'s Format 2 branch does. Return `''` if neither format
     matches. Trim/collapse whitespace and cap length similarly to
     `extractSetup` (slice to a reasonable max, e.g. 400 chars, for
     consistency with the rest of the file).
   - `extractAgeNotes(body)`: Format 1 — inline
     `**Age/division notes:**` bold section; Format 2 — a heading section
     matched via `headingSection(body, /^age/i)` (covers headings like
     `## Age/Division Notes`). Return `''` if neither matches. Same
     trimming/length-cap treatment.

4. In `loadDrills()`, add these fields to each pushed drill object:
   ```js
   stage:            fm.stage ? String(fm.stage) : stageFallback(Number(fm.age_min), String(fm.intensity)),
   prerequisites:    Array.isArray(fm.prerequisites) ? fm.prerequisites : (fm.prerequisites ? [fm.prerequisites] : []),
   progressionNotes: extractProgressionNotes(body),
   ageNotes:         extractAgeNotes(body),
   ```
   Track how many drills used an explicit `fm.stage` vs. the fallback (a
   simple counter incremented in the loop is fine).

5. After `loadDrills()` is called in the main script flow, add a
   `console.log` summarizing the counts, e.g.:
   `Stage tagging: <explicit> explicit, <fallback> computed via fallback (of <total> drills)`

6. In `loadStandardPlans()`'s `fieldMap`, add `'stage:': 'stage'` (and add
   `stage: ''` to the `current = { ... }` initializer alongside the other
   plan fields). In `finalizePlan(p, drillIndex, plans)`, when `p.stage` is
   falsy, derive it from `p.difficultyRange` via this lookup (case-sensitive
   match against the existing free-text values already in
   `standard-plans.md`):
   - `'Beginner'` → `'beginner'`
   - `'Beginner–Intermediate'` → `'beginner'`
   - `'Intermediate'` → `'intermediate'`
   - `'Intermediate–Advanced'` → `'intermediate'`
   - `'Advanced'` → `'advanced'`
   - anything else/empty → default `'beginner'` (add a code comment noting
     this default)
   Include the resolved `stage` in the plan object pushed to `plans`.

7. Run `npm run sync:drills -- --dry-run` and confirm it exits 0 with no
   errors and prints the new stage summary line. Then run
   `npm run sync:drills` for real to regenerate `src/drills-data.js`.

8. In `practice.js`, find `filterDrills()` and:
   - Add a `filterLevel` state variable near the top of the module (next to
     the existing `filterSkill`/`filterIntensity`/`filterAge` declarations),
     initialized to `''` (all levels).
   - Add a stage check: `if (filterLevel && d.stage !== filterLevel) return false;`
   - Extend the text-search join (the array that currently includes things
     like `d.title, d.category, d.purpose, d.skill`) to also include
     `d.progressionNotes || ''` and `d.ageNotes || ''`.

9. In `index.html`, locate the Drill Library filter controls block (near
   the existing `#pp-age-filter` select). Add a new `<select id="pdrill-level-filter">`
   with a label ("Level"), options: `All levels` (value `""`),
   `Introductory` (value `introductory`), `Beginner` (value `beginner`),
   `Intermediate` (value `intermediate`), `Advanced` (value `advanced`).
   Also find the existing `#pp-age-filter` select's top option
   (`<option value="14-18">14U+ (Junior/Senior)</option>`) and change it to
   `<option value="12-15">12–15U (Advanced)</option>`.

10. In `practice.js`, wire the new `#pdrill-level-filter` select's `change`
    event to set `filterLevel` and call `renderDrillCards()` — follow the
    exact same pattern used for the existing filter selects (look at how
    `#pp-age-filter`'s change handler is wired near line ~1789 for the
    pattern to copy).

11. In `practice.js`'s drill card renderer (the function that currently
    appends skill/intensity badges via `makeBadge`), add a Level badge:
    build a small `stage → display label` map (`introductory` → 'Introductory',
    `beginner` → 'Beginner', `intermediate` → 'Intermediate', `advanced` →

12. In `styles.css`, add 4 new badge color variants
    (`.pbadge-stage-introductory`, `.pbadge-stage-beginner`,
    `.pbadge-stage-intermediate`, `.pbadge-stage-advanced`) following the
    exact pattern of the existing `.pbadge-low`/`.pbadge-med`/`.pbadge-high`
    rules (same property structure, distinct but harmonious colors within
    the existing navy/red/cream brand palette — do not introduce new hex

13. In `practice.js`'s drill detail modal renderer, add:
    - A "How to progress" block: if `drill.progressionNotes` is non-empty,

    - A prerequisites row: if `drill.prerequisites.length > 0`, render a row

14. In `index.html`, add a new "Roadmap" tab/nav-item alongside the existing

    - Call `renderRoadmap()` when the Roadmap tab/section is activated,

## Acceptance Criteria

1. `npm run sync:drills -- --dry-run` exits 0 with no errors and prints a
   stage fallback/explicit summary line.
2. `npm run sync:drills` (real run) regenerates `src/drills-data.js` such
   that every drill record has a `stage` field with one of the 4 valid
   values, a `prerequisites` array, and `progressionNotes`/`ageNotes` string
   fields (possibly empty), and every plan record has a `stage` field.
3. No existing key on any drill or plan record in `src/drills-data.js` was
   removed or renamed (schema change is purely additive).
4. The Drill Library shows a working Level filter (Introductory/Beginner/
   Intermediate/Advanced/All) that narrows the visible drill cards
   according to each drill's `stage`.
5. The Age Range filter's top option reads "12–15U (Advanced)" instead of
   "14U+ (Junior/Senior)", and filtering by it behaves consistently with the
   other age-band options (overlap-match logic unchanged).
6. Drill cards display a Level badge alongside the existing skill/intensity
   badges.
7. The drill detail modal shows a "How to progress" note when
   `progressionNotes` is non-empty and prerequisite chips when
   `prerequisites` is non-empty, and shows neither block (no placeholder
   text) when those fields are empty.
8. Search (`filterDrills`) matches drills based on their `progressionNotes`/
   `ageNotes` text in addition to the previously-searched fields.
9. A new Roadmap view is reachable from the app's navigation and renders all
   10 skill categories, each as a 4-stage ladder (Introductory/Beginner/
   Intermediate/Advanced) with correct age-range labels (5–8U/8–10U/10–12U/
   12–15U).
10. Every skill×stage cell with no matching plan renders a visually distinct
    "Coming soon" placeholder card; no cell is silently omitted.
11. Clicking a populated Roadmap stage card's plan loads it into the plan
    builder using the same mechanism as the existing Skill-Focused Plans
    click-to-load behavior.
12. Existing save/load, export/import, and print/PDF flows are unaffected
    (no regressions).
13. `README.md` and `scripts/README.md` are updated to describe the new
    fields, the stage-fallback behavior, and the Roadmap view.
