## Goal

Add skill-level/progression data and a new "Roadmap" view to the Homerun
Practice drill library so it reads as a searchable, filterable, professional
path from Introductory (5–8U) through U15 (capped display at 12–15U), per
`docs/superpowers/specs/2026-08-19-drill-library-roadmap-design.md` (Track A
only). The sync script gains a `stage` field per drill/plan (explicit from
KB frontmatter when present, computed via a fallback table otherwise) plus
two new text fields (`progressionNotes`, `ageNotes`) parsed from KB content
that already exists but is currently discarded. The app then exposes a Level
filter, a Level badge, progression/prerequisite info in the drill detail
modal, and a new Roadmap view showing each skill category as a 4-stage
ladder that reuses the existing "load plan into builder" behavior. None of
this requires any KB content changes — the fallback table makes it fully
functional today, and it silently gets more accurate later without further
app changes.

## Constraints

- `src/drills-data.js` is generated by `scripts/sync-drills.mjs` — do not
  hand-edit `src/drills-data.js`; all field changes go through the sync
  script, then re-run the sync so `src/drills-data.js` reflects the change.
- The sync script's output schema changes must be purely additive — do not
  remove or rename any existing key on drill or plan records.
- Do not touch the five brand hex values, print/PDF output structure, or the
  save/load/export/import JSON formats.
- Reuse the existing Skill-Focused Plans "click to load into plan builder"
  code path for the Roadmap view's populated stage cards — do not build a
  parallel load mechanism.
- KB content (`/Users/jschasse/knowledge-base/youth-baseball-canada/wiki/drills/*.md`
  and `standard-plans.md`) is read-only source of truth for the sync script;
  do not edit KB files as part of this task (no new `stage:`/`prerequisites:`
  frontmatter is being added to KB files here — the fallback table covers
  every drill for now).
- All 10 skill categories must appear in the Roadmap view: throwing,
  infield, conditioning, catching, hitting, pitching, outfield, baserunning,
  situational, bunting.
- A skill×stage cell with no existing plan must render as a distinct
  "Coming soon" card, not be hidden — the roadmap always shows the full
  4-stage shape for every skill.
- Follow existing code style in `practice.js`/`styles.css`/`index.html`
  (vanilla JS, no build step, no new dependencies).

## Step-by-Step Implementation Plan

1. In `scripts/sync-drills.mjs`, add `stage` and `prerequisites` to the
   drill frontmatter parsing: read `fm.stage` (string) and `fm.prerequisites`
   (inline YAML list, already parsed generically by `parseFrontmatter`;
   default to `[]` when absent).
2. Add a `STAGE_FALLBACK` helper function that computes a stage from
   `ageMin`/`intensity` when `fm.stage` is absent, using this table:
   - `ageMin <= 8` → `introductory`
   - `ageMin` 9–10 and `intensity` low/medium → `beginner`
   - `ageMin` 9–10 and `intensity` high → `intermediate`
   - `ageMin` 11–12 (any intensity) → `intermediate`
   - `ageMin >= 13` → `advanced`
3. Add `progressionNotes` and `ageNotes` extractor functions mirroring the
   existing `extractSetup`/`extractCues` dual-format pattern:
   - `extractProgressionNotes(body)`: Format 1 — inline `**Progressions:**`
     bold section (same regex shape as `extractSetup`'s Format 1, but
     matching `Progressions`); Format 2 — `## Progressions` heading section
     via `headingSection`, joined into a paragraph. Default `''`.
   - `extractAgeNotes(body)`: Format 1 — inline `**Age/division notes:**`
     bold section; Format 2 — a heading section matching `/^age/i` (covers
     `## Age/Division Notes` or similar). Default `''`.
4. In `loadDrills()`, add `stage: fm.stage ? String(fm.stage) : STAGE_FALLBACK(ageMin, intensity)`,
   `prerequisites: Array.isArray(fm.prerequisites) ? fm.prerequisites : (fm.prerequisites ? [fm.prerequisites] : [])`,
   `progressionNotes: extractProgressionNotes(body)`, `ageNotes: extractAgeNotes(body)`
   to each drill record. Track a running count of fallback-vs-explicit stage
   assignments during the loop.
5. After `loadDrills()` returns in `main`, `console.log` a summary line,
   e.g. `Stage tagging: N explicit, M computed via fallback (of T drills)`.
6. In `loadStandardPlans`/`finalizePlan`, add a `stage:` field to the plan
   field map (`fieldMap['stage:'] = 'stage'`) and, in `finalizePlan`, when
   `p.stage` is empty, derive it from `p.difficultyRange` via a lookup:
   `Beginner` → `beginner`, `Beginner–Intermediate` → `beginner`,
   `Intermediate` → `intermediate`, `Intermediate–Advanced` → `intermediate`,
   `Advanced` → `advanced` (default `'beginner'` if `difficultyRange` is
   empty/unrecognized — document this default in a code comment). Include
   `stage` in the emitted plan object.
7. Run `npm run sync:drills -- --dry-run` and confirm 0 errors and a sane
   fallback/explicit summary line (expect ~all drills via fallback, since no
   KB frontmatter changes are part of this task); then run
   `npm run sync:drills` for real so `src/drills-data.js` picks up the new
   fields.
8. In `practice.js`, extend `filterDrills()`'s searchable-text join to
   include `d.progressionNotes || ''` and `d.ageNotes || ''`.
9. In `index.html`, add a `Level` `<select>` filter next to the existing
   Skill/Intensity/Age Range filters in the Drill Library controls (options:
   All levels / Introductory / Beginner / Intermediate / Advanced), and
   relabel the Age Range filter's top option from `14U+ (Junior/Senior)`
   value `14-18` to `12–15U (Advanced)` value `12-15`.
10. In `practice.js`, add `filterLevel` state (mirrors `filterSkill`), wire
    its `<select>`'s change handler, and add a `stage` check to
    `filterDrills()` (`if (filterLevel && d.stage !== filterLevel) return false;`).
11. In `practice.js`'s drill card renderer, add a Level badge next to the
    existing skill/intensity badges (reuse `makeBadge`, add a stage→label
    map and a `pbadge-stage-<stage>` CSS class hook).
12. In `styles.css`, add badge color variants for the 4 stage values
    (following the existing `pbadge-low/med/high` intensity pattern), plus
    styling for the new Roadmap view (ladder layout, stage cards, "coming
    soon" card variant) — reuse existing card/badge/button classes and
    tokens where possible rather than introducing a new visual language.
13. In `practice.js`'s drill detail modal renderer, add a "How to progress"
    block showing `drill.progressionNotes` when non-empty, and a
    prerequisites row of clickable chips (one per slug in
    `drill.prerequisites`) that open that drill's detail when non-empty;
    render nothing for either when empty (no placeholder text).
14. In `index.html`, add a new "Roadmap" section/tab alongside the existing
    Drill Library and Skill-Focused Plans sections (same nav pattern as the
    existing tabs), with a container for the per-skill ladders.
15. In `practice.js`, add a `renderRoadmap()` function: for each of the 10
    skill categories, build a 4-stage row (Introductory 5–8U → Beginner 8–10U
    → Intermediate 10–12U → Advanced 12–15U). For each skill×stage cell,
    find matching plan(s) from `ALL_PLANS` where `plan.skill === skill &&
    plan.stage === stage`; if any exist, render a card per plan (label, age
    range, drill count via `plan.drills.length`, duration via
    `plan.totalDuration`/`plan.totalMin`) whose click handler calls the same
    function the existing Skill-Focused Plans list uses to load a plan into
    the builder; if none exist, render a "Coming soon" placeholder card
    (distinct styling, no click handler). Wire `renderRoadmap()` to run when
    the Roadmap tab is activated (mirror how `renderDrillCards()` /
    Skill-Focused Plans rendering is triggered on tab switch).
16. Update `README.md`'s "Drill data" section to document `stage`,
    `prerequisites`, `progressionNotes`, `ageNotes`, and describe the new
    Roadmap view under "The Practice Planner" (numbered list item, matching
    the style of the existing items).
17. Update `scripts/README.md` to document the stage-fallback table and the
    fallback/explicit count the sync script now logs.
18. Manually verify (via the `run` skill or a local browser) that: the
    Roadmap renders all 10 skills × 4 stages with "Coming soon" cards
    everywhere no plan exists yet; a populated stage card loads its plan
    into the builder; the Level filter narrows the Drill Library grid;
    search matches text sourced from `progressionNotes`/`ageNotes` on drills
    that have it; existing save/load/export/import/print flows still work
    unchanged.
